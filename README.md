# Pigeon flock TDS pipeline

## Files
- `tds_core.py` — загрузка CSV, подготовка сигналов, расчёт TDS, пакетный прогон.
- `visualization.py` — визуализации: траектории, координаты, TDS heatmap, сравнение групп, lag traces.
- `run_analysis.py` — точка входа для запуска анализа на папке с CSV.

## Что делает алгоритм
1. Читает все CSV с разделителем `;`.
2. Разбирает пары столбцов `X_<bird>(m)` и `Y_<bird>(m)`.
3. Автоматически определяет группу по имени файла:
   - `ff*` -> `free_flight`
   - `hf*` -> `homing_flight`
4. Для каждого файла и каждой координаты (`x`, `y`) строит попарный TDS для всех птиц в стае.
5. Сохраняет:
   - `pairwise_tds_results.csv`
   - `lag_trace_results.csv`
   - `flock_summary.csv`
6. Строит картинки:
   - траектории стаи,
   - временные ряды координат,
   - тепловые карты TDS,
   - сравнение free vs homing,
   - lag trace для самой сильной пары.

## Как запустить
```bash
python run_analysis.py /path/to/csv_folder /path/to/output_folder
```

Для ваших файлов в текущей папке:
```bash
python run_analysis.py /mnt/data /mnt/data/tds_output
```

## Параметры по умолчанию
Используется сетка окон:
- `window_size=60`, `step_size=10`, `max_lag=10`
- `window_size=120`, `step_size=20`, `max_lag=15`
- `window_size=240`, `step_size=40`, `max_lag=20`

Если частота дискретизации ≈ 5 Гц, это соответствует окнам примерно 12, 24 и 48 секунд.

## Что считать TDS здесь
В коде реализован практический TDS-подход:
- ряд режется на скользящие окна,
- в каждом окне ищется лаг с максимальной корреляцией между двумя птицами,
- TDS = доля окон, где найденный лаг остаётся устойчивым в течение серии окон.

Это удобно для первого шага: сравнить, есть ли различия между типами полёта на уровне устойчивой синхронности.
